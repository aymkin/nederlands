# Frequentie — частотное ядро нидерландского (колода Alex)

Колода вне курсов: слова идут в порядке консенсусного частотного ранга, не по
темам учебника. Почему так и откуда числа —
`other/language_learning_methods/eroshev_frequentie_methode.md`; план и метрики
— `daily/frequentie_2026/plan.md`.

Нумерация файлов — по **партиям**, не по диапазону рангов. Партии 1–4 собраны из
пробела — слов, которых Alex не знал. С 2026-10-06 карточку получает каждое
слово списка подряд от ранга 1, знакомое тоже (план, 2.4: «не исключается из
очереди»); так появилась партия 5. Ранг пересчитывается при пересборке списка,
поэтому диапазон у партии плавающий. Первая партия названа `0001-0100` до того,
как это выяснилось; переименовывать не стали — имя ничего не ломает.

**Порядок — по рангу.** Позиция новой карточки в очереди Anki равна её `Rank`:
`import` и `update` партии Kern в конце сами запускают
`python3 scripts/anki_utils.py herorden`, а пресет вводит новые по колоде в
порядке позиции. День — следующие N рангов; правило грамматики попадает в
пример, только где ложится естественно. Тег — партия,
`frequentie::kern::partijNN`. Теги `frequentie::kern::dagNN` (до 05.10 день
партии подбирался под правило грамматики, `grammatica/README.md`) больше не
ставятся, у старых карточек остались.

Колоды генерируются только после гейта недели 2 плана (см. план, раздел 3).

## Note type «Frequentie NL» (создать в Anki один раз)

Существующие типы не подходят: `LINK Vocabulary` показывает нидерландское слово
спереди (направление NL → RU) и не имеет поля Audio; `Language Islands`
двусторонний (второй шаблон — лишняя работа, Mondria & Wiersma 2004) и без
примера. Новый тип — одна карточка, одно направление.

**Tools → Manage Note Types → Add → Add: Basic → имя `Frequentie NL`.** Затем
**Fields** — переименовать/добавить в этом порядке:

| #   | Поле                 | Содержимое                                                               |
| --- | -------------------- | ------------------------------------------------------------------------ |
| 1   | `Word`               | лемма с артиклем: `het gebruik`, `vertellen`; второе прочтение — `zijn²` |
| 2   | `Rank`               | ранг в списке, он же позиция новой карточки в очереди                    |
| 3   | `Example`            | одно короткое нидерландское предложение, i+1                             |
| 4   | `Translation`        | русский перевод (1–2 значения, не статья)                                |
| 5   | `TranslationExample` | перевод примера                                                          |
| 6   | `Audio`              | `[sound:freq_vertellen_3f2a1c.mp3]` — озвучка примера                    |

**Cards → шаблон «Card 1»** (единственный):

Front:

```html
<div class="direction">🇷🇺 → 🇳🇱</div>
<div class="translation">{{Translation}}</div>
<div class="context">{{TranslationExample}}</div>
```

Back:

```html
{{FrontSide}}
<hr id="answer" />
<div class="word">{{Word}}</div>
<div class="example">{{Example}}</div>
{{Audio}}
<div class="rank">#{{Rank}}</div>
```

Styling:

```css
.card {

}

  font-size: 30px;

  margin-top: 6px;

}

  color: #bbb;
  margin-top: 14px;

```

Почему именно так:

- **Русский пример спереди** — контекст, а не подсказка: он показывает, какое из
  значений имеется в виду (чайник-для-заварки против чайника-для-кипятка у
  Ерошева). Без него карточка раздражает ложными «ошибками».
- **Нидерландский пример и звук только сзади** — Barcroft 2004: при первом
  кодировании формы внимание не размазывать.
- **Одна карточка.** Обратная (NL → RU) не окупается: 49 % против 48 % при вдвое
  большей работе.
- **Ранг мелким сзади** — как у Ерошева: видно, насколько частое слово.

## Формат TSV для импорта

```
#separator:tab
#html:true
#notetype:Frequentie NL
#deck:Frequentie::Kern
#columns:Word	Rank	Example	Translation	TranslationExample	Audio	Tags
#tags column:7
```

**Имя mp3 — ключ списка и хэш примера, без ранга:**
`freq_{ключ}_{sha1(пример)[:6]}.mp3`, «#» в ключе — «-» (`freq_zijn-2_….mp3`).
Имя с рангом пришлось бы менять при каждой пересборке списка (так было до
2026-09-14). Хэш — с 2026-10-07: у переписанного примера новое имя, и устаревший
mp3 не зазвучит; у `zijn` и `zijn²` имена разные. Имена ставит и озвучивает
`kern.py audio` (ниже). На прежние `freq_{lemma}.mp3` не ссылается ни одна
заметка.

**Почему `Word` первым, а не `Rank`.** Anki определяет дубликаты по **первому
полю**: при повторном импорте строка с уже существующим первым полем обновляет
заметку, а не создаёт вторую. Ранг у нас меняется: пересборка списка 2026-10-06
сдвинула его у всех 321 заметки Kern. Если первым полем стоит `Rank`, такой
пересчёт превращает каждую карточку в новую: 1000 дублей и потерянные интервалы.
Лемма стабильна, поэтому ключ — она. Порядок исправлен 2026-09-14, до создания
типа в Anki; позже он стоил бы пересборки колоды.

Колонки разделены **литеральными табами** (`.prettierignore` уже исключает
`_anki.txt`). Теги: `frequentie::kern::0001-0100`, `frequentie::kern::partijNN`.
Директива `#notetype:` требует, чтобы тип уже существовал — отсюда ручной шаг
выше.

## Партия: от списка до Anki

**Список.** Ранги считает `private/frequentie_pilot/consensus_rank.py` (каталог
не публикуется) по OpenSubtitles 2018 и `wordfreq`: балл — взвешенное среднее
геометрическое рангов (0,55 / 0,45), равные баллы — по лемме, поэтому сборка
воспроизводима. Он пишет `lijst_v2.json` (ключи по рангу) и `vormen.json` (форма
→ ключи). Ошибки лемматизатора и омографы чинит `lijst_besluiten.tsv`: `remap`
переносит счёт формы или ключа на другой ключ, `lezing` делит форму по долям
частей речи SUBTLEX-NL (`zijn` — глагол `zijn` и местоимение `zijn²`), `uit` —
слово без карточки (имена, мат, английские вставки субтитров), `blijft` —
кандидат разобран, менять нечего. Второе прочтение — отдельное слово со своим
рангом; его Word на карточке — из таблицы (`zijn²`, `de bank²`). Без приватной
таблицы рядом со скриптом сборка и `kern.py` останавливаются.

**Шаги** (скрипты в `scripts/`, все — системным `python3`):

1. `kern.py lijst` — граница: первый ранг без карточки и без `uit`. Карточка у
   слова есть, если его даёт Word любой заметки «Frequentie NL» (Kern, Werk,
   Reading). Партия берёт ранги подряд от границы, без пропусков.
2. Пример — по i+1: все прочтения каждого слова, кроме цели, раньше цели в
   списке (в блоке 1–150 — любые из первых 150) или помечены `uit`. Свободны
   имена (заглавная не в начале предложения), числа цифрами, формы цели, у
   разорванного отделяемого глагола — частица и формы основы.
   `kern.py check FILE` — нарушений 0. «Часть прочтений впереди» — прочитать: в
   примере то прочтение, что уже известно (`morgen` «завтра», а не «утро»)?
3. `kern.py rank FILE` — колонка Rank := ранг в списке.
4. `kern.py audio FILE --droog`, затем без `--droog` — колонка Audio и озвучка
   недостающих mp3 (edge-tts, голос колоды Werk) прямо в `collection.media`.
   Пакет `edge-tts` стоит у системного `python3`, не в venv пилота.
5. Бэкап Anki, затем `anki_utils.py import FILE` — ворота (ниже), запись,
   `herorden`.

Правка уже импортированной заметки — в файле; затем `kern.py audio FILE --droog`
и `anki_utils.py update FILE --droog` называют каждое поле, которое изменится.
Потом бэкап, `kern.py audio FILE` (новому примеру — новое имя mp3 и озвучка) и
`update` без `--droog`; повторный `import` такую заметку пропускает.
`update --droog` по нескольким файлам сверяет каждый с нынешним Anki, а не с
файлами перед ним: синонимы из разных партий дают ложную остановку (2026-10-07,
`lijken`/`uitzien`).

Доли частей речи — из SUBTLEX-NL: Keuleers, Brysbaert & New (2010), «SUBTLEX-NL:
A new measure for Dutch word frequency based on film subtitles», Behavior
Research Methods 42, 643–650; лицензия CC BY-NC-SA 4.0. От них зависят строки
`lezing` и через них колонка Rank.

## Ворота: Twenty Rules, синонимы, i+1

`scripts/anki_utils.py import` и `update` не пишут в Anki, пока партия не
пройдёт проверку по всей коллекции «Frequentie NL» (Kern, Werk, Reading вместе);
`update` проверяет только заметки с изменённым `Translation` или `Example`:

- **правило 4** — в `Translation` не больше двух значений (`;` и `,`; скобки —
  пояснение, не значение);
- **правило 10** — первое значение `Translation` не совпадает с первым значением
  другого слова: на лицевой стороне RU → NL это и есть вопрос, и при совпадении
  верны оба ответа;
- **синонимы** — у заметок с общим значением своя ситуация: их примеры не делят
  ни одного слова, кроме самих целей и служебных (`LEEG` в `anki_utils.py`);
- **i+1** — только Kern, `kern.py check` по новым и изменённым примерам.

Раньше этой проверки, ещё без Anki, импорт отказывает партии с повтором `Word`:
`canAdd` сверяет заметку только с коллекцией, а `addNotes` на втором экземпляре
откатил бы всю партию.

Нарушение — список, код выхода 1, в Anki ничего не записано. После ручной правки
полей в Anki проверить коллекцию целиком: `python3 scripts/anki_utils.py lint`
(правила 4, 10 и синонимы). Команды работают только в профиле `alex`: при другом
открытом профиле они отказывают до проверки, иначе партия сравнивалась бы с
чужой, пустой коллекцией (2026-09-28). Что проверяет только человек — скилл
`anki-twenty-rules`; полный текст правил — MCP-промпт
`/mcp__anki__twenty_rules`.

Служебные слова отдельной колодой не идут: у них карточки Kern на своих рангах,
большинство — в блоке 1–150 (партия 5).

## Дневной цикл: утро Anki → день Fluent

1. **Утро.** Anki, колода `Frequentie`: сначала повторения, потом новые. Норма
   из плана: `Kern` — 20 в день понедельник–суббота (снижение до 15 — по условию
   плана, раздел 3), `Werk` — 5 в день ежедневно. Карточка раздражает третий раз
   — в архив (suspend), не мучиться. **Воскресенье — выходной по новым `Kern`:**
   его лимит новых 0, повторения обеих колод и новые `Werk` идут как обычно
   (пропущенный день повторений отдаёт очередь в понедельник вдвое). В Anki это
   Deck Options колоды `Kern` → отдельный preset или ручное «New cards/day = 0»
   на воскресенье.
2. **Мостик.**
   `python3 scripts/anki_vandaag.py --out private/frequentie/vandaag.md` —
   скрипт читает копию коллекции и выписывает слова, чьи карточки получили
   первое повторение сегодня. Файл в `private/`, не публикуется.
3. **День.** `/fluent-review` как обычно. Правило для Fluent (в `CLAUDE.md`,
   Tutor Mode): если `private/frequentie/vandaag.md` датирован сегодня,
   упражнения на `grammar_rule` строятся на этих словах — они попадают в
   предложения на инверсию, `omdat`-порядок, perfectum и т.д. Слова **не**
   попадают в `new_vocabulary[]`: их интервалы ведёт Anki, второй SRS на то же
   слово — двойная работа без прибавки.

Так одно и то же слово в один день встречается трижды в разном качестве:
извлечение формы по-русски (Anki), пример со звуком (Anki, оборот), и
употребление внутри грамматической конструкции (Fluent). Это ровно «качество
встречи», которое у Uchihara 2019 весит больше числа встреч.
