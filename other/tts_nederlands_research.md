## 1. Вывод (TL;DR)

**Оставить edge-tts как рабочую лошадку и добавить Azure AI Speech для
«парадных» историй.** Это не компромисс из лени — это следствие двух проверенных
фактов.

**Факт первый: три нидерландских голоса, которыми репозиторий уже пользуется, —
это ровно те же самые голоса, которые Azure продаёт за деньги.**
`nl-NL-ColetteNeural`, `nl-NL-FennaNeural`, `nl-NL-MaartenNeural` стоят в
официальном списке Azure как standard neural voices; edge-tts достаёт их же
через эндпоинт «Read Aloud» браузера Edge. То есть переход на платный Azure сам
по себе **не улучшит звук ни на процент**. Он даёт другое: легальный API вместо
реверс-инжиниринга, полноценный SSML (`<prosody rate>`, `<break>`), пословные
тайминги, несколько голосов в одном запросе — и доступ к более новым
нидерландским голосам `nl-NL-Fleur:MAI-Voice-2` / `nl-NL-Sander:MAI-Voice-2`,
которых у edge-tts нет (проверено локально: эндпоинт отдаёт 324 голоса, ни
одного с двоеточием в имени, а запрос `nl-NL-Sander:MAI-Voice-2` падает с
`ValueError: Invalid voice`).

**Факт второй: у edge-tts уже есть всё нужное для педагогики, просто это не
используется.** Локальная проверка на установленной версии 7.2.7:

- `--rate=-25%` реально растягивает речь: одна и та же нидерландская фраза 4.94
  с → 6.57 с (коэффициент 1.33, то есть 0.75× — как раз целевой диапазон
  0.7–0.9×). Работает на Maarten, Colette и nl-BE-Arnaud;
- `edge_tts.Communicate(..., boundary="WordBoundary")` отдаёт **пословные**
  тайминги (offset и duration в тиках по 100 нс) для `nl-NL-MaartenNeural`. У
  CLI такого флага нет — поэтому `story_reader.py`, который вызывает именно CLI,
  видит только сентенс-уровневые субтитры и вынужден добирать точность через
  Whisper.

Оба факта переводятся в конкретные патчи (раздел 5), и оба ничего не стоят.

### Слепой тест решил вопрос: edge-tts выиграл (2026-08-31)

Поскольку объективного бенчмарка с нидерландским не существует (раздел 6),
единственным способом сравнить «естественность» был слепой тест на ухо
владельца. Он проведён, и **edge-tts выбран как звучащий естественнее, чем
Google Chirp3-HD**.

Методика: фрагмент адаптированной истории (~1 100 знаков, авторский текст +
монолог персонажа), двухголосая сборка на каждом движке — рассказчик женским
голосом, персонаж мужским, склейка через ffmpeg с паузой 0,7 с. Пары голосов:
`nl-NL-Chirp3-HD-Kore` + `-Charon` против `nl-NL-ColetteNeural` +
`nl-NL-MaartenNeural`. Назначение A/B — через `$RANDOM`, мапинг записан в файл,
минуя вывод команды и контекст ассистента.

**Темп выровнен по замеру, а не на глаз** — иначе тест сравнивал бы скорость, а
не качество. Chirp3-HD синтезирован на `speakingRate 1.0`, замерен, коэффициент
вычислен как отношение к длительности edge-версии (`speakingRate = 0.718`).
Итог: 84,56 с против 87,20 с — расхождение 3 % при исходном разрыве 34 %.

Калибровка базовых темпов (одна фраза, `ffprobe`):

| Движок           | Настройка          | Длительность |
| ---------------- | ------------------ | ------------ |
| Chirp3-HD Kore   | `speakingRate 1.0` | 8,90 с       |
| Chirp3-HD Kore   | `speakingRate 0.8` | 11,02 с      |
| Chirp3-HD Kore   | `speakingRate 0.7` | 12,65 с      |
| Chirp3-HD Kore   | `speakingRate 0.6` | 14,74 с      |
| edge-tts Colette | `+0%`              | 11,93 с      |
| edge-tts Colette | `-20%`             | 14,90 с      |
| edge-tts Colette | `-30%`             | 17,04 с      |

Отсюда правило пересчёта, если Chirp3-HD когда-нибудь понадобится: его
`speakingRate 0.8` — это **обычный** темп edge-tts, а не замедленный;
педагогическому `-20%` соответствует примерно `0.6`. Множители темпа у вендоров
не сопоставимы напрямую, потому что каждый считает «1.0» от своей базы.

**Следствие:** миграция на Google отменяется. Остаются два бесплатных патча к
edge-tts из раздела 5. Chirp3-HD сохраняет одно неоспоримое преимущество — 30
нидерландских голосов против трёх (подтверждено на живом API: 34 голоса nl-NL
всего, из них 30 Chirp3-HD), поэтому он остаётся кандидатом на озвучку
второстепенных персонажей, если однажды понадобится больше трёх тембров. Проект
`nederlands-tts` заведён, биллинг привязан, API включён — возврат к эксперименту
не потребует настройки заново.

### Рекомендация

| Слой                   | Чем озвучивать                                     | Стоимость при 10–30 историях/мес     |
| ---------------------- | -------------------------------------------------- | ------------------------------------ |
| **Ежедневный объём**   | edge-tts + `--rate` + `boundary="WordBoundary"`    | $0                                   |
| **«Парадные» истории** | Azure AI Speech, tier F0                           | $0 (в пределах 0.5 млн символов/мес) |
| **Runner-up**          | Google Cloud TTS, `nl-NL-Chirp3-HD-*` (30 голосов) | $0, но проиграл слепой тест          |

Почему Azure, а не Google, на второй позиции: Azure — единственный вендор, у
которого **один и тот же тир** закрывает сразу три требования — управление
темпом через SSML, пословные тайминги и несколько голосов в одном документе. У
Google премиальный нидерландский тир Chirp3-HD (30 голосов, лучшее разнообразие
и, вероятно, лучший звук) **не поддерживает тег `<mark>`** — значит, никаких
timepoints, а вся архитектура `story_reader.py` держится на таймингах.

Почему Google всё-таки runner-up, а не отброшен: 30 нидерландских голосов против
трёх — это качественно другой выбор для персонажей, встроенное управление темпом
0.25–2× и разметка пауз `[pause short]` / `[pause long]`, и главное — 1 млн
символов в месяц бесплатно. Отсутствие таймингов лечится тем же приёмом, что и
всё остальное: синтезировать **по предложению** и склеивать через ffmpeg. Тогда
границы точны по построению, и вендор перестаёт иметь значение.

**Чего делать не стоит.** ElevenLabs ($6–22/мес) оправдан только если нужен
многоголосый диалог с идеальной интонацией — для A2-чтения это перерасход:
нидерландский там поддержан через мультиязычные модели, а не отдельным
нидерландским тиром. OpenAI TTS дёшев ($0.90–2.70/мес), но **не отдаёт таймингов
вообще** и не публикует списка языков для TTS — только ссылку на языки Whisper.
Deepgram Aura-2 имеет девять честных нидерландских голосов, но стоит $30 за
миллион символов, таймингов не отдаёт, а про параметр `speed` его собственная
документация пишет «Not yet supported in all languages».

**И последнее, самое неприятное.** Объективного бенчмарка нидерландского TTS
найти не удалось: TTS Arena фактически англоязычна, а языковой состав TTSDS2
проверить не получилось (сайт недоступен, в тексте статьи слово «Dutch» не
встречается ни разу). Значит, **любое утверждение «X звучит по-нидерландски
лучше» — это либо маркетинг вендора, либо ваше собственное измерение**.
Практический вывод: прежде чем платить, прогнать один и тот же `verhaal_*.md`
через edge-tts, Azure MAI-Voice-2 и Google Chirp3-HD и послушать. Это полчаса
работы — и они закрывают вопрос надёжнее любой таблицы ниже.

## 2. Критерии оценки

1. **Настоящая поддержка nl-NL.** Не «70+ языков!», а именованный список
   нидерландских голосов в официальной документации. Если списка нет — это
   отдельная находка, и она фиксируется.
2. **Педагогическая пригодность для A2–B1.** Управление темпом (нужно 0.7–0.9×),
   внятная артикуляция, возможность вставлять паузы. Есть ли `<prosody rate>`,
   параметр `speed`, `speaking_rate`?
3. **Вывод по предложениям.** `story_reader.py` нужен тайминг на каждое
   предложение (синхронная подсветка), `audio_to_anki.py` — отдельный аудиофайл
   на предложение. Значит: либо API отдаёт word/sentence-тайминги, либо его
   можно дёшево вызывать по предложению.
4. **Многоголосье.** В историях есть рассказчик и персонажи. Кто умеет несколько
   говорящих в одном запросе?
5. **Стоимость на реальном объёме.** 6 000 символов на историю, 10–30 историй в
   месяц (60–180 тыс. символов). Цена — с указанием страницы и даты чтения.
6. **Интеграция с Python.** Официальный SDK, документированный HTTP API, CLI,
   локальный вариант.
7. **Лицензия для личного учебного использования.**

**Проверка допущения про 6 000 символов.** Замер по девяти существующим
`verhaal_*.md` через `story_reader.parse_sentences()` + `strip_md()` (то есть
ровно тот текст, который уходит в TTS): медиана — 3 294 символа, минимум — 1
587, максимум — 23 889, среднее — 7 765. Допущение 6 000 символов на историю
консервативно, но адекватно.

**И заодно — сколько это минут.** Два независимых замера на реальном тексте
(`daily/verhalen/verhaal_2026-04-03_de_verdwenen_laptop.md`, голос
`nl-NL-MaartenNeural`) дали согласованный результат:

| Объём текста | `+0%`                     | `-25%` (0.75×)             |
| ------------ | ------------------------- | -------------------------- |
| 1 171 символ | 87.8 с → **800 симв/мин** | 117.1 с → **600 симв/мин** |
| 3 431 символ | 4.35 мин → 789 симв/мин   | 5.80 мин → 591 симв/мин    |

Отсюда пересчёт, который понадобится в разделе про Azure: **6 000 символов — это
7.5 минуты на нормальной скорости и ровно 10.0 минуты на 0.75×**. Типичная же
история (медиана 3 294 символа) — 4.1 и 5.5 минуты соответственно.

## 4. Разбор по кандидатам

### 4.1 edge-tts — текущая база

**Что это на самом деле.** CLI сам себя описывает так: «Text-to-speech using
Microsoft Edge's online TTS service». Явного дисклеймера «не аффилировано с
Microsoft» в README нет (файл всего 76 строк) — но описание репозитория говорит
прямо: использовать сервис Edge «WITHOUT needing Microsoft Edge or Windows or an
API key». Технические следы реверс-инжиниринга видны в исходниках: WebSocket
ведёт на
`wss://speech.platform.bing.com/consumer/speech/synthesize/readaloud/edge/v1`
(из трейсбека в issue #401), а токен `Sec-MS-GEC` генерируется на клиенте в
`src/edge_tts/drm.py`. Это потребительский эндпоинт браузера, а не
опубликованный API Azure.

**Нидерландский набор голосов** — проверено локально, `edge-tts --list-voices`
на версии 7.2.7 (всего 324 голоса):

```
nl-BE-ArnaudNeural    Male    Friendly, Positive
nl-BE-DenaNeural      Female  Friendly, Positive
nl-NL-ColetteNeural   Female  Friendly, Positive
nl-NL-FennaNeural     Female  Friendly, Positive
nl-NL-MaartenNeural   Male    Friendly, Positive
```

Ни один голос в списке не содержит двоеточия — то есть новые семейства Azure
(MAI-Voice, DragonHD) через этот эндпоинт недоступны. Прямая проверка:

```
$ edge-tts -t "Goedemiddag." -v "nl-NL-Sander:MAI-Voice-2" --write-media x.mp3
ValueError: Invalid voice 'nl-NL-Sander:MAI-Voice-2'.
```

**Управление темпом.** Флаги `--rate`, `--volume`, `--pitch` (значения по
умолчанию `+0%`, `+0%`, `+0Hz`); README предупреждает: «When using a negative
value, you will need to use `--[option]=-50%` instead of `--[option] -50%`».
Замер длительности одной и той же фразы
(`Ik woon in Hilversum. Morgen ga ik naar de markt.`):

| Голос               | `+0%`  | `-25%` | Коэффициент  |
| ------------------- | ------ | ------ | ------------ |
| nl-NL-MaartenNeural | 4.94 с | 6.57 с | 1.33 (0.75×) |
| nl-NL-ColetteNeural | 5.24 с | 6.98 с | 1.33 (0.75×) |
| nl-BE-ArnaudNeural  | 4.58 с | 6.10 с | 1.33 (0.75×) |

То есть заявленное значение честно отражается в длительности, а не имитируется
ресемплингом.

**SSML недоступен, и это принципиально.** README формулирует прямо: «Support for
custom SSML was removed because Microsoft prevents the use of any SSML that
could not be generated by Microsoft Edge itself. This means that all the cases
where custom SSML would be useful cannot be supported as the service only
permits a single `<voice>` tag with a single `<prosody>` tag inside it.»
Следствия: нет `<break time="600ms"/>` для управляемых пауз, нет нескольких
голосов в одном запросе. Единственный рычаг для пауз — разделять предложения
пустой строкой, что `text_to_speech.py:generate_whole_audio()` уже и делает.

**Тайминги — главная находка.** Конструктор:

```python
Communicate(text, voice, *, rate="+0%", volume="+0%", pitch="+0Hz",
            boundary: Literal["WordBoundary", "SentenceBoundary"] = "SentenceBoundary", ...)
```

По умолчанию — сентенс-уровень, и у CLI флага для переключения нет. Поэтому
`--write-subtitles` даёт по одной реплике на предложение (проверено: две фразы →
две cue-строки, причём таймкоды с запятыми, то есть формат SRT, а не VTT —
`story_reader.parse_vtt()` принимает оба). Но через Python API:

```python
Communicate(text, "nl-NL-MaartenNeural", rate="-25%", boundary="WordBoundary")
```

выдаёт
`{'type': 'WordBoundary', 'offset': 1000000, 'duration': 3166660, 'text': 'Ik'}`
и так далее по каждому слову. Это ровно то, чего `story_reader.py` сейчас
добивается через Whisper.

обновлялся (`pushed_at: 2026-03-22`). Открытые issue касаются именно
стабильности эндпоинта: #473 «Intermittent 'No audio was received' errors with

Историческая картина повторяется: #290, #344, #401, #452, #458 — все про 403/503

новым реверс-инжинирингом. 11 827 звёзд, но пять месяцев без коммитов при
открытых багах надёжности.

### 4.2 Azure AI Speech — официальный путь к тем же (и лучшим) голосам

**Нидерландские голоса** (страница language support, вкладка TTS):

| Голос                            | Локаль | Пол | Тир                     |
| -------------------------------- | ------ | --- | ----------------------- |
| `nl-NL-FennaNeural`              | nl-NL  | Ж   | standard neural         |
| `nl-NL-MaartenNeural`            | nl-NL  | М   | standard neural         |
| `nl-NL-ColetteNeural`            | nl-NL  | Ж   | standard neural         |
| `nl-NL-Fleur:MAI-Voice-2`        | nl-NL  | Ж   | MAI-Voice-2 (preview)   |
| `nl-NL-Fleur:MAI-Voice-2-Flash`  | nl-NL  | Ж   | MAI-Voice-2-Flash       |
| `nl-NL-Sander:MAI-Voice-2`       | nl-NL  | М   | MAI-Voice-2 (13 стилей) |
| `nl-NL-Sander:MAI-Voice-2-Flash` | nl-NL  | М   | MAI-Voice-2-Flash       |
| `nl-BE-DenaNeural`               | nl-BE  | Ж   | standard neural         |
| `nl-BE-ArnaudNeural`             | nl-BE  | М   | standard neural         |

**Нидерландского DragonHD не существует.** Полный список DragonHD-голосов
покрывает только de-DE, en-US, es-ES, fr-FR, ja-JP, zh-CN. DragonHD Flash — ещё
уже: «HD Flash only supports text in `zh-CN` and `en-US`». DragonHD Omni
заявляет 700+ голосов и правило имени
`languagelocale-voicename:DragonHDOmniLatestNeural`, но **пофамильного списка
для nl-NL не публикует** — это ровно тот пробел, который стоит зафиксировать:
заявка есть, подтверждения по языку нет.

**И самое важное про HD-тиры: они не умеют управлять темпом.** Собственная
таблица Azure:

| Элемент SSML | DragonHD | Dragon HD Omni |
| ------------ | -------- | -------------- |
| `<prosody>`  | No       | No             |
| `<break>`    | Yes      | No             |
| `<bookmark>` | No       | No             |
| `<lang>`     | Yes      | Yes            |

Вместо `rate` у Omni есть `cfg_scale` (диапазон 1.0–2.0; «Lower values
(1.0–1.2): Slower speech with less contextual alignment»). Для ученика, которому
нужен предсказуемый 0.8×, это хуже, чем честный `<prosody rate="-20%">`. Вывод,
который переворачивает обычную интуицию «дороже = лучше»: **для обучения
правильный тир — не HD, а обычный neural**, потому что только он поддерживает
полный SSML.

**Управление темпом и паузами (standard neural).** `<prosody rate>` принимает
множитель, процент или константу; ограничение прямо в документации: «The rate
changes should be within `0.5` to `2` times the original audio». Константы:
`x-slow` (-50%), `slow` (-46%), `medium`, `fast` (+55%), `x-fast` (+100%).
`<break time>` принимает `500ms` / `2s`, допустимо 0–20000 мс; `strength`
принимает `x-weak` (250 мс) … `x-strong` (1250 мс).

**Тайминги.** Событие WordBoundary даёт смещение в тиках (1 тик = 100 нс),
длительность, текст слова и смещение слова во входном тексте — то есть настоящий
пословный уровень. Отдельно `<bookmark mark="..."/>` + событие BookmarkReached
позволяют получить смещение произвольной точки. Из HD-тиров word boundary
поддерживает только Dragon HD Omni.

**Многоголосье.** Обычный SSML допускает несколько тегов `<voice>` в одном
документе; квота — «Maximum total number of distinct `<voice>` and `<audio>`
tags in SSML: 50» и на F0, и на S0. Для истории с рассказчиком и двумя-тремя
персонажами этого более чем достаточно.

**Цены.** Со страницы тарифов Speech: standard neural и Neural HD Flash —
**$15.00 за 1 млн символов**, Neural HD — **$22.00 за 1 млн символов**, custom
professional voice — $24.00/$48.00, personal voice — $24.00. Бесплатный тир
формулируется как «0.5 million characters free per month». Цифра $15
перепроверяется в независимом документе по квотам: «Multiply the result by the
unit price of $15 per million characters».

Важная деталь биллинга: считаются **все** символы, включая пробелы, знаки
препинания и всю разметку SSML, кроме тегов `<speak>` и `<voice>`. То есть паузы
`<break>` тоже стоят денег.

**Ограничения F0, из-за которых архитектуру придётся выбирать осознанно:**

| Квота                    | F0                  | S0               |
| ------------------------ | ------------------- | ---------------- |
| Транзакции real-time TTS | **20 за 60 секунд** | 30 TPS (до 1000) |
| Максимум аудио на запрос | 10 минут            | 10 минут         |
| Batch synthesis          | **недоступен**      | доступен         |

20 запросов в минуту — это один запрос каждые три секунды. Для истории из 73
предложений (реальная цифра из
`daily/verhalen/verhaal_2026-04-03_de_verdwenen_laptop.md`) поштучный синтез
займёт около 3.7 минут. Терпимо, но именно поэтому на Azure логичнее один запрос
на всю историю плюс WordBoundary — а нарезку делать локально через ffmpeg.
Ограничение в 10 минут аудио на запрос при этом упирается ровно в наш расчётный
объём: по замеру из раздела 2, 6 000 символов на 0.75× — это **10.0 минуты**, то
есть буквально на границе. Типичная история (медиана 3 294 символа, 5.5 минуты
на 0.75×) проходит одним запросом с запасом, а длинные (19–24 тыс. символов)
придётся делить.

**SDK.** `azure-cognitiveservices-speech` 1.51.2 (20.08.2026), колёса для macOS
arm64 (11.0+) есть; страница требований подтверждает macOS 10.14+ на x64 или
Arm64.

**MAI-Voice-2 — что известно и чего нет.** Модель в public preview,
позиционируется как «highest-fidelity, most expressive», «ideal for expressive
long-form content, educational content, Audiobooks/Podcasts». Нидерландских
голосов два: `nl-NL-Fleur:MAI-Voice-2` (без стилей) и `nl-NL-Sander:MAI-Voice-2`
(13 стилей: `adventurous`, `caring`, `empathy`, `curious`, `encouraging`,
`excited`, `friendly`, `cheerful`, `nostalgic`, `reflective`, `sad`,
`disappointed`, `serious`). У Flash-варианта нидерландский только мужской
(Sander). Работает через тот же Speech SDK и то же SSML. **Но таблицы поддержки
SSML для MAI-тира Microsoft не публикует**, поэтому работает ли `<prosody rate>`
на `nl-NL-Sander:MAI-Voice-2` — неизвестно, и к какому SKU в тарифах он
относится ($15 или $22) — тоже. Это надо проверять экспериментом, а не
документацией.

### 4.3 Google Cloud Text-to-Speech

**Нидерландский по тирам** — это главный результат по Google, потому что
премиальные тиры у него распределены по языкам крайне неравномерно:

| Тир           | nl-NL                                                | nl-BE           |
| ------------- | ---------------------------------------------------- | --------------- |
| Standard      | да — `nl-NL-Standard-F`, `-G`                        | да — `-C`, `-D` |
| WaveNet       | да — `nl-NL-Wavenet-F`, `-G`                         | да — `-C`, `-D` |
| **Neural2**   | **нет**                                              | нет             |
| **Studio**    | **нет**                                              | нет             |
| **Polyglot**  | **нет**                                              | нет             |
| **Chirp3-HD** | **да — 30 голосов** (`-Achernar` … `-Zubenelgenubi`) | да — 30         |

То есть предположение «премиум только для английского» верно для Neural2, Studio
и Polyglot — но **неверно** для Chirp3-HD, самого нового тира: там нидерландский
покрыт щедрее, чем у любого другого вендора в этом обзоре.

**Chirp3-HD: что можно и чего нельзя.** Управление темпом встроенное — «values
ranging from 0.25x (very slow) to 2x (very fast)». Есть разметка пауз
`[pause short]`, `[pause long]`, `[pause]` с длительностью, которую модель
подбирает по контексту. SSML поддерживается ограниченным белым списком, и
формулировка честная: «Any tags that are not on this list will be ignored during
the synthesis process. Note that SSML tags are not currently supported for
streaming requests.» В список входят `<speak>`, `<say-as>`, `<p>`, `<s>`,
`<phoneme>`, `<sub>`, `<break>`, `<audio>`, `<prosody>`, `<voice>` — то есть
`<prosody rate>` и `<break>` работают. **`<mark>` в список не входит** →
timepoints на Chirp3-HD получить нельзя (тег будет молча проигнорирован).
Управление паузами недоступно в 15 локалях; нидерландского среди них нет.

**Timepoints.** Общая страница SSML: «You can set a timepoint in your script
using the `<mark>` tag… Set `TimepointType` to `SSML_MARK`. If this field is not
set, timepoints are not returned by default.» Ограничений по тирам на этой
странице нет, но из белого списка Chirp3-HD следует практический вывод: **нужны
тайминги — берите Standard или WaveNet**, у которых SSML не урезан.

**Многоголосье — нидерландский GA.** Отдельная страница «Create dialogue with
multiple speakers» (модели `gemini-2.5-flash-tts`, `gemini-2.5-pro-tts`,
`gemini-3.1-flash-tts-preview`, тип `MultiSpeakerMarkup` в том же Python SDK)
перечисляет 64 языка, и «Dutch (Netherlands) | nl-NL | GA». Это опровергает
распространённое представление, что multi-speaker у Google только en-US. Оплата,
правда, идёт по токенам Gemini-TTS, а не по символам.

**Цены** (прочитано из исходного HTML страницы тарифов; сами таблицы
подгружаются скриптом, но числа лежат в разметке):

| WaveNet                        | 0–4 000 000 (тот же SKU) | **$4 / 1 млн**                                                    |
| Neural2                        | 0–1 000 000              | **$16 / 1 млн**                                                   |

| Studio                         | 0–1 000 000              | **$160 / 1 млн**                                                  |

### 4.4 Amazon Polly

**Нидерландские голоса и движки** (таблица available-voices):

| Голос | Локаль | Пол | Generative | Long-form | Neural | Standard |
| ----- | ------ | --- | ---------- | --------- | ------ | -------- |
| Laura | nl-NL  | Ж   | **да**     | нет       | **да** | нет      |
| Lotte | nl-NL  | Ж   | нет        | нет       | нет    | да       |

Итог: generative-движок для нидерландского **есть** (Laura и Lisa), long-form —
**нет ни для одного** нидерландского голоса. Lotte и Ruben — старые
standard-голоса.

**SSML.** «All tags except for `<amazon:domain name="news">` are supported for
Standard voices.» Для остальных движков — таблица; ключевые строки: `<break>` —
full на neural / long-form / generative; `<prosody>` — partial на всех трёх;
`<emphasis>` — недоступен нигде. Что означает «partial», уточняет отдельная
страница: «Generative, Neural, and Long-Form voices support the `volume` and
`rate` attributes, but don't support the `pitch` attribute. For Generative
voices, the prosody tag can be used only around full sentences.» То есть
**`<prosody rate>` работает на всех движках**, включая generative; теряется
только `pitch`. Неподдерживаемый тег на standard/neural/long-form даёт ошибку, а
не тихое игнорирование.

**Speech marks — сильная сторона Polly для этого репозитория.** «Speechmarks are
available when using neural, long-form, or standard text-to-speech engines.»
Generative в списке отсутствует. Типы: `sentence`, `word`, `viseme`, `ssml`
(последний возвращает смещения `<mark>`), запрашиваются параметром
`SpeechMarkTypes`. Наличие типа **`sentence`** — редкость среди вендоров и точно
совпадает с тем, что нужно `story_reader.py`. Практический вывод: для
нидерландского с таймингами — Laura/Lisa в режиме **neural**, а не generative.

**Цены** (страница тарифов Polly): Standard — «$4.00 per 1 million characters»,
Neural — «$16.00 per 1 million characters», Long-Form — «$100.00 per 1 million
characters», Generative — «$30 per 1 million characters».

Бесплатный тир, дословно: Standard — «5 million characters per month for speech
or Speech Marks requests» (**без оговорки «первые 12 месяцев»**); Neural — «1
million characters per month… for the first 12 months»; Long-Form — 500
тыс./мес, первые 12 месяцев; Generative — 100 тыс./мес для speech-запросов,
первые 12 месяцев. Асимметрия существенная: у Standard бесплатный объём
бессрочный.

| Голос / движок            | Первый год                  | После 12 месяцев    |
| ------------------------- | --------------------------- | ------------------- |
| Lotte / Ruben (standard)  | $0                          | $0 (тир бессрочный) |
| Laura / Lisa (neural)     | $0 (до 1 млн)               | $0.96 – $2.88 / мес |
| Laura / Lisa (generative) | $0 при 60k; ~$2.40 при 180k | $1.80 – $5.40 / мес |

**Новее ничего нет.** Nova Sonic: «Expressive voices are offered… in five
languages: English (US, UK), French, Italian, German, and Spanish» — без
нидерландского. Nova 2 Sonic (декабрь 2025): английский, французский,
итальянский, немецкий, испанский, португальский, хинди — тоже без

Обратите внимание на лимит v3 в 5 000 символов: история на 6 000 символов уже не
влезает в один запрос лучшей модели. Отдельного нидерландского тира или
именованных nl-голосов нет — нидерландский покрыт мультиязычными моделями. В
Voice Library фильтр по языку содержит `<option value="nl">Dutch</option>`, то
есть нидерландские голоса сообществом залиты. **Документированной шкалы качества
по языкам вендор не публикует** — ещё один пробел того же типа, что у OpenAI.

**Темп.** `voice_settings.speed`, значение по умолчанию 1.0; документация:
«Values below 1.0 will slow the voice down, to a minimum of 0.7. Values above
1.0 will speed up the voice, to a maximum of 1.2.» Нижняя граница 0.7 буквально
совпадает с нижней границей педагогического диапазона — запаса нет, но и
хватает.

**Тайминги.** Эндпоинт `text-to-speech/…/with-timestamps` возвращает
**посимвольное** выравнивание: `characters`, `character_start_times_seconds`,
`character_end_times_seconds` (в объектах `alignment` и `normalized_alignment`).
Для границ предложений это даже точнее, чем нужно.

**Многоголосье.** Text to Dialogue существует, лимит 2 000 символов на запрос.
Поддержка нидерландского **на самой странице этого эндпоинта не подтверждена**

### 4.6 OpenAI TTS

**Модели:** `tts-1`, `tts-1-hd`, `gpt-4o-mini-tts` («our newest and most
reliable text-to-speech model»). Ничего новее на 2026-08-31 не найдено. Обратите
внимание: `platform.openai.com/docs/*` теперь редиректит на
`developers.openai.com/api/docs/*`.

**Языки — здесь и находится главный пробел.** Документация говорит: «The TTS
model generally follows the Whisper model in terms of language support», со
ссылкой на список языков Whisper; во встроенном перечислении нидерландский
присутствует («…Croatian, Czech, Danish, **Dutch**, English…»). Но **отдельного
списка поддерживаемых языков именно для TTS, тем более по голосам, OpenAI не
публикует** — поддержка выводится по ссылке на модель распознавания речи. Для
языка, который у большинства вендоров идёт «вторым сортом», это слабое
основание.

**Управление подачей.** Параметр `instructions` (до 4096 символов) —
единственный в обзоре способ сказать модели словами «читай медленно и
отчётливо»; ограничение: «Does not work with `tts-1` or `tts-1-hd`», то есть
только `gpt-4o-mini-tts`. Параметр `speed` — «Select a value from `0.25` to
`4.0`. `1.0` is the default», исключений по моделям не отмечено.

**Таймингов нет.** На странице API-референса `createSpeech` слово «timestamp» не
встречается ни разу; `response_format` допускает только `mp3`, `opus`, `aac`,
`flac`, `wav`, `pcm`. Вариант `verbose_json` с таймингами существует у
отдельного эндпоинта транскрипции (STT), а не у TTS. Многоголосья в одном
запросе тоже нет.

**Цены:** `tts-1` — «$15.00 / 1M characters», `tts-1-hd` — «$30.00 / 1M
characters». `gpt-4o-mini-tts` тарифицируется **по токенам**: вход $0.60 за 1
млн текстовых токенов, аудиовыход $12.00 за 1 млн аудио-токенов. Опубликованного
коэффициента «символы → аудио-токены» нет, поэтому стоимость истории для этой
модели честно посчитать нельзя. Для символьных моделей: 60 тыс. символов — $0.90
(`tts-1`) / $1.80 (`tts-1-hd`); 180 тыс. — $2.70 / $5.40.

**SDK.** `openai` — официальный.

## 5. Что это значит для этого репозитория

Разобрано по фактическому коду трёх скриптов, а не в общих словах.

### 5.1 `scripts/text_to_speech.py` — добавить `--rate`, это самый дешёвый выигрыш

Сейчас словарь `VOICES` содержит три голоса nl-NL, а оба генератора вызывают
`edge_tts.Communicate(text, voice)` **без** параметра `rate` — то есть весь
материал репозитория озвучен на `+0%`, полной скоростью носителя. Для A2 это
главный педагогический дефект текущей озвучки, и он лечится одним аргументом:

- добавить `--rate` (по умолчанию, скажем, `-15%` или оставить `+0%` и указывать
  явно) и передать его в `Communicate(...)` в `generate_all_audio()` и
  `generate_whole_audio()`. Замер выше: `-25%` даёт ровно 0.75× по длительности;
- можно расширить `VOICES` двумя nl-BE-голосами (`nl-BE-ArnaudNeural`,
  `nl-BE-DenaNeural`) — они подтверждённо доступны и дают фламандский вариант
  для разнообразия персонажей;
- пауз через SSML здесь не будет никогда: edge-tts блокирует пользовательский
  SSML. Приём `"\n\n".join(...)` в `generate_whole_audio()` — единственный
  доступный рычаг, и его стоит оставить как есть. Управляемые паузы
  (`<break time="600ms"/>`) появляются только на платном пути — Azure, Polly или
  Google.

### 5.2 `scripts/story_reader.py` — отсюда можно убрать Whisper

Сейчас `generate_tts()` вызывает **CLI** `edge-tts` с `--write-subtitles`. Из-за
того, что у CLI нет флага `--boundary`, субтитры приходят сентенс-уровневыми
(проверено), и точность добирается двумя обходными путями: `match_timings()`
жадно склеивает cue-строки под предложения, а `align_timings_whisper()` (путь по
умолчанию, если `openai-whisper` импортируется) прогоняет Whisper и сопоставляет
слова через `SequenceMatcher` с порогом схожести 0.6 и последующей интерполяцией
пропусков в `_interpolate_gaps()`. То есть текст, который **уже точно
известен**, прогоняется через распознавание речи, чтобы узнать, когда он звучит.

Два способа это убрать — оба ломают меньше, чем кажется:

**Вариант A, минимальный (остаёмся на edge-tts).** Заменить вызов CLI на Python
API с `boundary="WordBoundary"`. Тогда приходит поток слов с точными смещениями,
и — ключевое отличие от Whisper — **текст этих слов берётся из входа, а не из
распознавания**. Значит, сопоставление предложения со словами становится точным
проходом по последовательности, а не нечётким матчингом; порог 0.6, интерполяция
и зависимость `openai-whisper` из пути ридера уходят. Один запрос на историю.

Это проверено не на фразе, а на целой истории:
`daily/verhalen/verhaal_2026-04-03_de_verdwenen_laptop.md` (3 431 символ
narrated-текста) прошёл одним запросом на `nl-NL-MaartenNeural` с `rate="-25%"`
и `boundary="WordBoundary"` и вернул **607 пословных тайминг-событий на 5.80
минуты аудио**. То есть данных для точной разметки 73 предложений приходит с
десятикратным запасом, и Whisper для этого не нужен.

**Вариант B, вендор-независимый.** Синтезировать **по предложению** и склеивать
через ffmpeg. Тогда границы точны по построению (это просто накопленные
длительности), и работает с любым движком — включая те, у которых таймингов нет
вообще (Google Chirp3-HD, OpenAI, Deepgram). Шаблон склейки в репозитории уже
есть: `concat_audio()` в `scripts/parkiet_test.py` делает именно это через
`apad` + `concat`. Побочная выгода: те же нарезанные файлы — это готовые клипы
для карточек Anki, то есть вариант B закрывает потребности `story_reader.py` и
`audio_to_anki.py` одним проходом.

Ещё одна деталь плеера: в HTML-шаблоне `rates=[.7,.85,1,1.25,1.5]` меняет
`playbackRate` в браузере, то есть замедление делается ресемплингом на клиенте.
Серверное `--rate` звучит чище. Если пробросить темп в генерацию, «1×» в плеере
уже будет реальным 0.8×, а ползунок останется для тонкой подстройки.

### 5.3 `scripts/audio_to_anki.py` — выбор TTS его не меняет

Этот скрипт выравнивает **учебные** MP3 из курса, у которых никаких метаданных
нет по определению. Поэтому Whisper здесь остаётся необходимым, и никакой выбор
TTS-вендора этого не меняет. Два замечания по существу:

- модель Whisper зашита как `base` (README прямо указывает строку ~104 и
  предлагает менять на `small`/`medium`). Собственные примеры README показывают
  характерные ошибки на нидерландском (`fysiotherapeut` → `visu-terap`,
  `Notenbomenlaan` → `noot een wonenlaan`); при съезжающих границах логично
  поднять до `small`. Это тангенциально к выбору TTS, но лежит на том же пути;
- для **TTS**-карточек скрипт вообще не нужен: `text_to_speech.py` уже
  генерирует по одному MP3 на предложение напрямую (`generate_all_audio()` →
  `{prefix}_sentence_{NNN}.mp3`) и сразу пишет TSV. Если вариант B из 5.2 будет
  реализован, `story_reader.py` начнёт производить те же клипы, и связка
  «ридер + Anki» станет одним конвейером.

### 5.4 Инфраструктурные последствия

- Сгенерированные MP3 попадают в репозиторий, а репозиторий целиком публикуется
  на GitHub Pages при каждом push в `main`. Прецедент уже есть: 52 файла
  `parkiet_test_audio/*.mp3` опубликованы. Объём аудио стоит держать в голове.
- Форматирование не пострадает: `.prettierignore` уже исключает `*.mp3` и
  `*_reader.html`, а `**/verhaal_*.md` — вообще из проверки Prettier.
- Если брать платный путь, ключ нужен только один (Azure или Google) — оба SDK
  ставятся из PyPI и оба официально поддерживают macOS arm64; локально сейчас
  установлен только `edge-tts` (через brew) и `whisper` (в `~/.local/bin`).

## 6. Открытые вопросы / что нельзя было проверить

Честный список того, что первоисточниками закрыть не удалось.

**Azure**

- Таблица поддержки SSML для тира MAI-Voice не публикуется → работает ли
  `<prosody rate>` (то есть замедление до 0.8×) на `nl-NL-Sander:MAI-Voice-2` —
  **неизвестно**. Это ключевая неопределённость для рекомендации «парадного»
  голоса.
- К какому SKU в тарифах относятся MAI-голоса — $15 (Neural HD Flash) или $22
  (Neural HD) — из документации не следует.
- DragonHD Omni: заявлено 700+ голосов и правило имени, но списка голосов для
  nl-NL нет → есть ли `nl-NL-*:DragonHDOmniLatestNeural`, не подтверждено.
- Microsoft Product Terms / условия использования для личного учебного
  применения не читались; на странице тарифов запрета на F0 для личных целей
  нет, но сам документ условий не проверен.

**Google**

- Область действия бесплатного лимита (на проект или на биллинг-аккаунт) на
  странице тарифов не указана — сказано только «per month».
- Стоимость Gemini-TTS (в том числе многоголосого нидерландского диалога) —
  токенная, коэффициент «символы → аудио-токены» не опубликован → цену истории
  посчитать нельзя.

**OpenAI**

- Стоимость `gpt-4o-mini-tts` за историю **не вычислима** по той же причине.
- Нет per-language списка для TTS — качество нидерландского из документации
  оценить нельзя вообще никак.

**Остальные**

- ElevenLabs: поддержка нидерландского **эндпоинтом** Text to Dialogue на его
  странице не заявлена.
- Cartesia: публичной ставки за символ нет; равенство «1 кредит = 1 символ» —
  **вывод** из соотношения 20 000 кредитов ≈ 27 минут, а не цитата.
- Deepgram: `speed` помечен «Not yet supported in all languages» → работает ли
  на нидерландском, не подтверждено. Официальность Python SDK по прочитанным
  страницам не подтверждена.
- Speechify: публичных цен нет; нидерландский помечен как «Beta».
- Higgs Audio v3: «100+ languages» без перечня → нидерландский не подтверждён.
- Fish Audio S2: поддержка Apple Silicon в официальном README не найдена.
- TTSDS2: есть ли нидерландский среди 14 языков — **не установлено**
  (`ttsdsbenchmark.com` недоступен 2026-08-31, в тексте статьи «Dutch» не
  встречается).
- TTS Arena V2: формулировку «только английский» от самого проекта дословно
  подтвердить не удалось (вывод сделан по родственной арене).

**И главное, что здесь не проверено вообще: как это звучит.** Никакого
прослушивания в рамках этой работы не проводилось. Документ отвечает на вопрос
«что технически возможно, за сколько и на каких условиях», но не на вопрос «чей
нидерландский приятнее и понятнее для A2». При отсутствии объективного бенчмарка
(раздел 4.11) второй вопрос решается только слепым тестом на одном и том же
`verhaal_*.md`.
