# Дизайн: мост «учебная программа → Fluent»

- **Дата:** 2026-06-26
- **Статус:** утверждён, готов к плану реализации
- **Учащийся:** Alex (курс Link praktisch; та же схема позже для De Opmaat)

## Проблема

Реальная учёба Alex (Link, De Opmaat) живёт в этом репозитории: woordenlijsten,
грамматика, тексты. Плагин Fluent при этом сам придумывает контент для
`/fluent-vocab` и `/fluent-learn`. Ежедневное интервальное повторение —
а вся система Fluent построена вокруг ежедневного `/fluent-review` — крутит
материал, оторванный от того, что у Alex реально на столе (сейчас Link thema 8
в Danner). Нужно, чтобы движок повторения работал по настоящей программе.

## Требования

1. **Последовательность.** Материал проходится по порядку (тема → taak).
2. **Сигнал перехода.** Учащийся должен понимать, когда хватит фокусироваться
   на текущей теме и пора на следующую.
3. **Fluent владеет интервалами.** Расписание и рециклинг — на SM-2 внутри
   Fluent.
4. **Переиспользовать существующее.** Точка входа — `new_vocabulary[]` в
   `update-db.py`; источник лексики — индексы из `build_vocab_index.py` и
   `*woordenlijst*_anki.txt`.
5. **Подключаемые модули грамматики.** Уметь скармливать в Fluent выбранные
   модули грамматики из `link/gramatica/grammatica_themaNN_*.md`.
6. **Рециклинг бесплатно.** Не строить отдельную логику рециклинга — это и есть
   SM-2.

## Не-цели (YAGNI)

- Не создавать отдельную директорию с дублированными текстами — контент уже в
  `link/` и `de_opmaat/`.
- Не заменять Anki как SR для узнавания лексики (если учащийся захочет — отдельно).
- Не делать автоматический переход между темами — переход подтверждается руками.
- Без GUI, без listening/speaking — только лексика и грамматика в текст.

## Разделение хозяев

Два требования — две независимые оси, у каждой свой владелец:

| Ось                       | Вопрос                                  | Владелец            |
| ------------------------- | --------------------------------------- | ------------------- |
| Последовательность/прогресс | какой пул активен, когда дальше       | Manifest (репо)     |
| Интервалы/рециклинг/освоенность | когда карточка всплывает, что освоено | Fluent (SM-2)       |

Не пересекаются: manifest выбирает **какой пул активен**, SM-2 решает **когда
внутри пула всплывает каждая карточка**.

## Что такое SM-2 (контекст)

SuperMemo 2: каждая карточка хранит `easiness_factor` (старт 2.5),
`interval_days`, `repetitions`. После ответа ставится `quality` 0–5.
`quality ≥ 3` → интервал растёт (1 → 6 → `interval × EF`); `quality < 3` →
`repetitions=0`, интервал назад на 1 день. `mastery_level` 0–5 копится с
повторениями. Рециклинг = трудное всплывает часто, освоенное всё реже.

## Архитектура — 3 слоя

```
link/curriculum.json  ──(active unit)──►  scripts/fluent_import.py
   (последовательность,                       │
    прогресс: done/active/locked)             │ new_vocabulary[]
                                              ▼
                                       update-db.py  ──►  spaced-repetition.json
                                                              (SM-2, очередь)
                                              ▲
   scripts/fluent_import.py --check  ──(read)─┘
   (порог освоенности по префиксу item_id → «пора дальше?»)
```

### Слой 1 — Manifest

Файл `link/curriculum.json` (аналогично `de_opmaat/curriculum.json`).

```json
{
  "course": "link",
  "units": [
    {
      "id": "thema_8",
      "grammar_file": "grammatica_thema08_in_mijn_buurt.md",
      "grammar_modules": "all",
      "status": "active"
    },
    {
      "id": "thema_9",
      "grammar_file": "grammatica_thema09_is_dat_wel_veilig.md",
      "grammar_modules": "all",
      "status": "locked"
    }
  ]
}
```

Семантика:

- `status`: `done` (пройдено) / `active` (текущее) / `locked` (ещё не открыто).
  **Ровно один** `active` за раз.
- `grammar_modules`: `"all"` или список номеров секций (`["2.1", "2.2"]`) —
  это и есть «необходимые модули».
- Порядок юнитов в массиве = последовательность прохождения.
- Прогресс версионируется в репо (а не в памяти ассистента).
- Юнит = **тема**; все её taak импортируются разом. Гранулярность taak — в
  будущем, если понадобится (см. Открытые вопросы).

### Слой 2 — Импортёр

`scripts/fluent_import.py --course link` (без флагов — берёт `active` юнит).

**Лексика.** Для активного юнита читает его `*woordenlijst*_anki.txt`
(колонки `Word | Example | Translation | TranslationExample | Tags`). Каждая
строка → элемент:

```json
{
  "item_id": "link_t8_voc_taak1_de-buurt",
  "item_type": "vocabulary",
  "content": "de buurt",
  "answer": "район, квартал",
  "category": "link_thema8",
  "priority": "medium"
}
```

Направление по умолчанию: `content` = NL, `answer` = RU. Fluent сам ротирует
recognition/production/cloze на повторении. Пример-предложение в схему Fluent не
кладётся (схема знает только content/answer/category/difficulty) — остаётся в
репо, тутор подтягивает контекст при повторении по `item_id`.

**Грамматика.** Для каждой выбранной секции `## N.N` грамматического файла
находит блок `### Voorbeelden uit oefeningen`. Каждый буллет с **жирной**
формой → cloze:

- источник: `Ik **werk** in Rotterdam.`
- `content`: `Ik ___ in Rotterdam. (модуль: Het werkwoord — ik-vorm)`
- `answer`: `werk`
- `item_type`: `grammar_rule`, `category`: `grammar_thema8`
- `item_id`: `link_t8_gram_2.1_3` (секция + порядковый номер примера)

Модуль без жирных примеров (только таблица) **пропускается** и логируется как
«не импортировано автоматически» — карточки на пустом месте не выдумываем.

**Отправка.** Собирает `new_vocabulary[]`, формирует payload с обязательными
`session_id` (`import-link-thema8-2026-06-26`) и `date`, пайпит в `update-db.py`.
`update-db.py` добавляет только новые `item_id` (`if item_id not in items`) и
перестраивает очередь — отсюда **идемпотентность**: повторный запуск дублей не
плодит, старые карточки продолжают рециклиться.

### Слой 3 — Гейт перехода

`scripts/fluent_import.py --check` (чистое чтение `spaced-repetition.json`):

1. Берёт `active` юнит из manifest, выводит префикс (`link_t8_`).
2. Фильтрует карточки Fluent по префиксу `item_id`.
3. Считает: доля с `mastery_level ≥ 3` и число «красных»
   (`consecutive_incorrect ≥ 2`).
4. Порог: **≥ 80% на `mastery_level ≥ 3` И 0 красных** → готов дальше.

```
Thema 8 — 24 карточки | mastery≥3: 20/24 (83%) | красных: 0
✅ готов к thema 9   →   запусти: fluent_import.py --advance
```

`--advance`: меняет `active → done`, следующий `locked → active`, затем
импортирует новый юнит. Переход подтверждается руками — гейт только советует.

## Поток данных

1. Один раз: создать `link/curriculum.json`, отметить `thema_8` как `active`.
2. `fluent_import.py --course link` → карточки темы 8 в Fluent.
3. Ежедневно: `/fluent-review` (SM-2 крутит и рециклит карточки темы 8).
4. Периодически: `fluent_import.py --check` → смотрит, дозрел ли юнит.
5. При ✅: `fluent_import.py --advance` → тема 9 становится активной и
   импортируется. Карточки темы 8 остаются в Fluent и продолжают рециклиться.

## Известный нюанс реализации

`update-db.py` трактует любой payload как «сессию»: безусловно инкрементит
`total_sessions`, стрик, пишет строку в session-log. Импорт — не занятие.

**Митигация (для плана):** добавить импортёру режим, который для импортов шлёт
payload с `duration_minutes: 0` и без `skill_scores`, ИЛИ добавить в `update-db.py`
флаг `--import`, пропускающий инкремент сессии/стрика. Правка официального
скрипта плагина хрупка (перезатирается при обновлении), поэтому
предпочтительно — отдельная функция/режим на стороне импортёра. Решается в
плане; не блокер дизайна.

## Тестирование

Минимальные проверки (без фреймворков):

- **Парсер грамматики:** на `grammatica_thema04_lekker.md` извлечь cloze из
  жирных примеров секции `2.1`; assert, что `Ik **werk** in Rotterdam` →
  `content` с `___` и `answer == "werk"`.
- **Идемпотентность:** прогнать импорт дважды на фикстуре, assert — число
  `items` не изменилось после второго прогона.
- **Математика гейта:** на фикстуре `spaced-repetition.json` с известными
  mastery — assert корректный вердикт относительно порога 80% / 0 красных.

## Изменения после реализации

- **Фокус на теме `--thema N` / `--taak N` (2026-06-27).** Добавлен override:
  импорт и `--check` принимают `--thema N` (и `--taak N`), чтобы работать с
  произвольной темой **без** сдвига активного указателя в manifest. Закрывает
  пункт «гранулярность taak» из «Открытых вопросов».

- **Резолв грамматики (2026-06-26).** В ходе реализации репозиторий был
  реорганизован: грамматика тем переезжает из `link/gramatica/` внутрь папок тем
  (`link/thema_N/grammatica_themaNN_*.md`). Импортёр ищет `grammar_file` (голое
  имя) сначала в папке темы, затем — fallback на `link/gramatica/`. `grammar_file`
  в manifest хранит только имя файла, без префикса каталога.

## Открытые вопросы / будущее

- Manifest для `de_opmaat/` — та же схема, отдельный файл.
- Переход между CEFR-уровнями (A2 → B1) — пока вне рамок; «уровень» здесь =
  следующая тема.
- Гранулярность taak (импорт/гейт по отдельным taak внутри темы) — добавить,
  если потемная окажется слишком крупной.
- Перенос примеров-предложений в карточку Fluent — сейчас контекст
  регенерируется тутором; пересмотреть, если повторения теряют качество.
