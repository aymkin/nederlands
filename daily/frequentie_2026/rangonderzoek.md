# Консенсусный ранг лемм для нидерландского — исследование 2026-09-14

Заказ: собрать ранг лемм по современному нидерландскому с фокусом на
повседневную жизнь и профессию (программист); зафиксировать единицу счёта. План,
который это обслуживает: `plan.md`. Код и данные: `private/frequentie_pilot/`
(gitignored).

## 1. Единица счёта — зафиксировано

| Что делаем               | В чём считаем  | Почему                                                                                                |
| ------------------------ | -------------- | ----------------------------------------------------------------------------------------------------- |
| Учим и ранжируем         | **леммы**      | `werken`, `werkt`, `gewerkt` — один предмет изучения, а не три; ранг присваивается лемме              |
| Измеряем покрытие текста | **словоформы** | текст состоит из форм; форма, которую не разобрал, не становится понятной оттого, что знаешь её лемму |

Оба числа считаются в одном скрипте (`consensus_rank.py`) и печатаются рядом,
чтобы их нельзя было перепутать. Практическое следствие: фраза «топ-2000
закрывает 88 %» означает «2000 **лемм** закрывают 88 % **словоформ** корпуса».

## 2. Источники и метод

| Код | Источник                                                           | Регистр                         | Вес       |
| --- | ------------------------------------------------------------------ | ------------------------------- | --------- |
| S1  | OpenSubtitles NL 2018 (hermitdave/FrequencyWords), 258 млн токенов | устная речь, быт                | 0,55      |
| S2  | `wordfreq` для `nl`, 60 000 верхних форм                           | смешанный: письменный + устный  | 0,45      |
| D1  | woordenlijst-индексы `link/` + `de_opmaat/`, 1434 леммы            | быт в Нидерландах по отбору NT2 | аннотация |
| D2  | курируемый список IT и офисной лексики, ранги измерены             | профессия                       | аннотация |

Ранг = взвешенное геометрическое среднее рангов в S1 и S2; лемма попадает в
ядро, только если засвидетельствована в **обоих** корпусах. Домены не
подмешиваются в ранг: специализированный корпус искажает общий ранг, а
утверждения Ципфа о покрытии верны только внутри своего жанра. Поэтому D1 и D2 —
пометки на леммах, а не слагаемые.

Список Hazenberg & Hulstijn (третий источник по исходному плану, вес 30) **не
использован**: надёжного доступа к нему нет, копии на файлопомойках непригодны
как источник. Веса перенормированы с 40/35 на 0,55/0,45.

## 3. Результат

Ядро: **25 191 лемма**, засвидетельствованная в обоих корпусах.

Покрытие корпуса субтитров словоформами:

| Лемм в ядре | Покрытие словоформ |
| ----------- | ------------------ |
| 500         | 80,1 %             |
| 1000        | 84,7 %             |
| 2000        | 88,4 %             |
| 3000        | 90,4 %             |
| 5000        | 92,4 %             |

Пробел (консенсусный топ-3000 минус выученное в Anki, минус NT2-курсы): **1693
леммы**, из них 252 в топ-1000 и 644 в полосе 1001–2000.

Все 21 слово сегодняшней партии подтвердились: остались в топ-1000, медианный
сдвиг ранга +5. Наибольший сдвиг — `meneer` 233 → 481: форма обращения из
субтитров, в письменном языке заметно реже.

## 4. Предсказания против факта

Числа записаны до запуска (правило `nederlands-research-methodology`).

| #   | Предсказание                              | Факт                 | Итог |
| --- | ----------------------------------------- | -------------------- | ---- |
| 1   | пересечение топ-2000 двух корпусов ≈ 68 % | 70 %                 | ✅   |
| 2   | криминальный кластер уедет за топ-1500    | все шесть в топ-620  | ❌   |
| 3   | IT-лексика почти целиком вне топ-3000     | 47 % внутри топ-2000 | ❌   |

**Почему провалилось 2.** Корпуса не независимы: `wordfreq` для нидерландского
сам включает субтитровые данные. «Консенсус» двух пересекающихся источников
усредняет меньше, чем кажется, и жанровый перекос переживает усреднение. Это
ограничение метода, а не случайность; чинится только добавлением независимого
корпуса (новости, официальные тексты).

**Почему провалилось 3.** Нидерландский IT не изобретает слова, а переиспользует
общие: `zoeken` (144), `fout` (391), `systeem` (686), `opdracht` (843), `waarde`
(963), `functie` (1325). Специальным оказывается не словарь, а сочетаемость.
Вывод для плана: отдельный «IT-модуль» нужен гораздо меньше, чем предполагалось,
— профессиональная лексика приходит вместе с ядром, а тренировать надо
употребление.

## 5. Методологическая находка: словарный фильтр резал нужное

Первая версия отбраковывала леммы по `simplemma.is_known`. Фильтр выбросил:

| Слово            | Вхождений в субтитрах | Причина                                  |
| ---------------- | --------------------- | ---------------------------------------- |
| `samenwerken`    | 6201                  | отделяемый глагол → лемма `samen_werken` |
| `uitvoeren`      | 4438                  | то же                                    |
| `website`        | 3533                  | композит → `web_site`                    |
| `software`       | 2051                  | англицизм, в словаре отсутствует         |
| `leidinggevende` | 1059                  | нидерландский композит                   |

То есть фильтр систематически наказывал три категории, на которых язык стоит:
композиты, отделяемые глаголы и обжившиеся англицизмы — ровно то, что нужно и в
быту, и в IT. Правило переписано: вес несёт засвидетельствованность в двух
корпусах, словарь решает только судьбу коротких токенов, плюс явный список
субтитровых заполнителей (`um`, `uh`, `tja`, `the`). Ядро выросло 17 034 → 25
191, покрытие топ-2000 поднялось 87,5 → 88,4 %.

Плата за это — остаточный шум лемматизатора (`godin`, `wangeloven`) проходит в
список. Он снимается при подготовке партии, а не фильтром: цена ошибки разная.
Пропущенный мусор стоит тридцати секунд на вычитке, выброшенный `samenwerken` —
незамеченной дыры в ядре.

## 6. Домены: где что лежит

Доля внутри консенсусного топ-2000:

| Слой                    | Внутри топ-2000 |
| ----------------------- | --------------- |
| Офис и работа           | 21 из 37 (56 %) |
| Повседневная жизнь в NL | 21 из 38 (55 %) |
| IT и программирование   | 28 из 59 (47 %) |

Вне ядра остаётся то, что частотно в своём домене и редко вообще: `gemeente`
(1274, но в `wordfreq` — 309: письменный ирегистр), `huisarts` (5146),
`apotheek` (4551), `factuur` (5672), `toeslag` (вне), `programmeur` (вне
топ-8000), `browser`, `applicatie`, `besturingssysteem`.

Отсюда практический вывод: **два маленьких модуля поверх ядра**, а не два
больших. Бытовой административный (gemeente, huisarts, verzekering, toeslag,
factuur, formulier, aanvragen) — порядка 40 слов, и он важнее по последствиям
ошибки, чем его ранг. Профессиональный — порядка 20 слов, остальное придёт с
ядром.

## 7. Ограничения

1. Два корпуса частично пересекаются (см. §4) — «консенсус» слабее заявленного.
2. Оба корпуса смещены к устной и сетевой речи. Официальный нидерландский
   (письма gemeente, страховые, счета) не представлен ни одним источником, а
   именно он даёт худшие последствия при непонимании.
3. Профессиональный слой собран курированием, а не из корпуса: попытка снять
   корпус с nl.wikipedia упёрлась в HTTP 429 по IP (четыре попытки с backoff).
   Ранги при этом измерены, курирован только отбор кандидатов.
4. Лемматизация `simplemma` даёт артефакты на композитах и именах собственных.

Чем чинить: независимый письменный корпус (новости NOS/Jeugdjournaal) третьим
источником; он же даст честный тест покрытия — измерять покрытие ядра на том же
корпусе, из которого ядро построено, значит льстить себе.
